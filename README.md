# HosRegis Document Assistant

ส่วนขยาย Chrome สำหรับช่วยตรวจเอกสารคำร้องขึ้นทะเบียนสถานพยาบาลในระบบ
HealthLink (hosregis.healthlink.go.th)

เครื่องมือนี้ทำหน้าที่ **ตรวจและตั้ง flag ให้เจ้าหน้าที่พิจารณา**
ไม่ติ๊ก checklist ให้อัตโนมัติ และไม่บันทึกผลใด ๆ ลงระบบ

---

## 1. ติดตั้ง

1. แตกไฟล์ zip ออกมาเป็นโฟลเดอร์
2. เปิด Chrome ไปที่ `chrome://extensions`
3. เปิด **Developer mode** (มุมขวาบน)
4. กด **Load unpacked** แล้วเลือกโฟลเดอร์นี้
5. เข้าเว็บ hosregis.healthlink.go.th และล็อกอินตามปกติ

ทุกครั้งที่แก้ไฟล์ในโฟลเดอร์ ต้องกดปุ่ม reload ที่การ์ดของส่วนขยาย
ใน `chrome://extensions` แล้ว reload หน้าเว็บด้วย

---

## 2. ตั้งค่า

เปิด Side Panel โดยกดไอคอนส่วนขยายบน toolbar ขณะอยู่บนหน้า hosregis
แล้วเลื่อนไปที่การ์ด **ตั้งค่า AI Triage**

| ช่อง | ความหมาย |
|---|---|
| Gemini API Key | ใส่ key ของคุณเอง เก็บใน chrome.storage ของเครื่องนี้เท่านั้น |
| Model | ค่าเริ่มต้น `gemini-2.5-flash` |
| วิธีดึงข้อมูลจากเอกสาร | เลือกโหมด (ดูข้อ 3) |
| สแกนเอกสารอัตโนมัติ | เปิดไว้ = พอเปิดหน้าคำร้องจะสแกนให้เลย |

กด **บันทึกการตั้งค่า**

---

## 3. โหมดการดึงข้อมูล

### Parser อย่างเดียว (ค่าเริ่มต้น)

OCR ด้วย Tesseract ในเครื่อง แล้วดึงข้อมูลด้วย regex parser
**ไม่มีข้อมูลใดออกจากเครื่อง** ใช้เวลาประมาณ 25 วินาทีต่อเอกสาร 1 ฉบับ

### Parser + AI

ส่ง **ไฟล์เอกสารทั้งฉบับ** (รวมสำเนาบัตรประชาชน) ไปยัง Gemini
อ่านลายมือ ตราประทับ และสแกนคุณภาพต่ำได้ดีกว่ามาก และเร็วกว่า
ถ้า AI ล้มเหลวจะกลับไปใช้ OCR ในเครื่องอัตโนมัติ

**ก่อนใช้โหมดนี้** ควรตรวจสอบว่า API key อยู่บน paid tier
เพราะ free tier ของ Gemini API จะนำข้อมูลไปใช้ปรับปรุงโมเดล
สำหรับสำเนาบัตรประชาชนควรพิจารณา PDPA และ Vertex AI (มี DPA และเลือก region ได้) ด้วย

---

## 4. ตรวจทีละคำร้อง

1. เปิดหน้า `/admin/checklist/<id>` (กดไอคอนเอกสารในตาราง)
2. ถ้าเปิด auto scan ไว้ ระบบจะสแกนเองภายในไม่กี่วินาที
   ถ้าไม่ ให้กด **สแกนเอกสาร**
3. อ่านผลจากการ์ดต่าง ๆ

| การ์ด | บอกอะไร |
|---|---|
| ข้อมูลคำร้อง | HCode, ชื่อ, ประเภท, ผู้มีอำนาจ, HA |
| Rule-Based Checks | ตรวจความครบถ้วนของฟอร์ม, เลขบัตร checksum, ข้อตกลง, สถานพยาบาลซ้ำ |
| แผนผังการตรวจสอบ | เทียบ "ค่าในฟอร์ม" กับ "ค่าในเอกสาร" ทีละรายการ พร้อมผล ตรงกัน / ไม่ตรง / ตรวจเอง |
| เปรียบเทียบข้อมูล | รายละเอียดการเทียบแบบเต็ม |
| AI Triage Summary | สรุปสั้น ๆ จากผลการตรวจ (ไม่ส่งข้อมูลส่วนบุคคล) |

การ์ด **แผนผังการตรวจสอบ** มีส่วน "ไม่มีหลักฐานจากเอกสาร" ท้ายสุด
แสดงรายการ checklist ที่ระบบตรวจให้ไม่ได้ ต้องดูเอง

---

## 5. Automate All (ตรวจทุกคำร้อง)

1. ไปที่หน้า `/admin/health_unit`
2. กดปุ่ม **Automate All** มุมขวาล่าง
3. ใส่จำนวนรายการที่ต้องการตรวจละเอียด (0 = ตรวจระดับทะเบียนอย่างเดียว)

ทำงาน 2 ระดับ

**ระดับทะเบียน** ตรวจครบทุกรายการในระบบ (ประมาณ 3,000 รายการ) ภายในไม่กี่วินาที
โดยไม่ต้องเปิดหน้าใด ตรวจสถานพยาบาลซ้ำ, รหัสหาย, ชื่อทั่วไป,
เจ้าของยื่นหลายคำร้อง, SLA ค้างนาน

**ระดับคำร้อง** เปิดทีละหน้าเพื่อตรวจข้อตกลง เลขบัตร และเอกสาร
ประมาณ 3-5 วินาทีต่อรายการ จึงจำกัดจำนวนไว้

เมื่อเสร็จจะเปิด **แท็บรายงานฉบับเต็ม** ให้อัตโนมัติ มีสรุป,
กลุ่มสถานพยาบาลซ้ำพร้อมลิงก์ไปแต่ละรายการ, และตารางรายการที่ติด flag ทั้งหมด

---

## 6. การตรวจสอบสถานพยาบาลซ้ำ

| ระดับ | เงื่อนไข | ผล |
|---|---|---|
| ซ้ำชัดเจน | รหัสหน่วยบริการซ้ำ หรือ ชื่อ + เจ้าของซ้ำ | fail |
| ชื่อคล้าย | ชื่อตรงกันแต่คนละเจ้าของ | ต้อง review |
| ชื่อทั่วไป | ชื่อที่ใช้ซ้ำกันเกิน 10 ราย เช่น "เอกชน" | ข้ามการตรวจด้วยชื่อ |

ชื่อทั่วไปจะถูกกรองออกอัตโนมัติ ไม่งั้นจะได้ false positive เป็นร้อยรายการ

---

## 7. สิ่งที่เครื่องมือนี้ไม่ทำ

- ไม่ติ๊ก checklist ให้อัตโนมัติ
- ไม่กดบันทึก ไม่แก้ไขข้อมูลใด ๆ ในระบบ
- ไม่อนุมัติหรือปฏิเสธคำร้อง

ปุ่ม **ติ๊กเลือกทั้งหมด** เป็นการติ๊กด้วยมือของคุณเอง จะถามยืนยันก่อน
และติ๊กเฉพาะช่อง checklist ของเจ้าหน้าที่ ไม่แตะช่องยอมรับข้อตกลงของผู้สมัคร

---

## 8. ข้อจำกัดที่ควรรู้

**ลายมือและลายเซ็น** Tesseract อ่านไม่ได้เลย โมเดล tha ฝึกมาจากตัวพิมพ์เท่านั้น
ถ้าจำเป็นต้องอ่านลายมือ ต้องใช้โหมด Parser + AI

**วันหมดอายุ** สแกนคุณภาพต่ำมักอ่านวันที่ไม่ได้ ระบบจะรายงานว่า
"ต้องตรวจด้วยตนเอง" แทนที่จะเดา และถ้าได้วันที่เก่าเกิน 10 ปี
จะถือว่าอ่านผิดแทนที่จะสรุปว่าหมดอายุ

**ข้อความกฎหมายท้ายใบอนุญาต** ใบ สพ.7 / สพ.19 ทุกใบมีข้อความบทลงโทษ
ซึ่งมีคำว่า "สถานพยาบาล" อยู่ด้วย parser จะกรองทิ้ง ถ้ากรองไม่ได้จะไม่ดึงค่าเลย
ดีกว่าดึงค่าผิดแล้วขึ้นว่าไม่ตรง

**หน้า checklist ของระบบ** ปุ่ม ถัดไป / กลับ ของเว็บเลื่อนทีละ 2 ขั้น
(ข้ามขั้นที่ 2) เครื่องมือจึงไม่ใช้ปุ่มพวกนี้ แต่อ่าน URL เอกสารทั้ง 4 ฉบับ
จาก DOM โดยตรง

## 9. แก้ปัญหาเบื้องต้น

| อาการ | วิธีแก้ |
|---|---|
| Side Panel ว่าง | reload หน้าเว็บ ต้องอยู่บน /admin/ ของ hosregis |
| ไม่พบเอกสาร | reload ส่วนขยาย แล้ว reload หน้าเว็บ |
| AI Error เรื่อง API key | ใส่ key ในตั้งค่า แล้วกดบันทึก |
| OCR ค้างนาน | ปกติ 25 วินาทีต่อฉบับ ครั้งแรกต้องโหลด language data ด้วย |
| ตรวจซ้ำทั้งระบบไม่สำเร็จ | ต้องเปิดหน้า /admin/health_unit ค้างไว้ |

ดู log เพิ่มเติมได้ที่ Console ของหน้าเว็บ (ข้อความขึ้นต้นด้วย `[HL]`)
และ Console ของ Side Panel (คลิกขวาใน panel แล้ว Inspect)

## 10. โครงสร้างไฟล์

```
manifest.json         ตั้งค่าส่วนขยาย permission และ CSP
background.js         service worker เรียก Gemini API และดึงไฟล์เอกสาร
content.js            ทำงานบนหน้าเว็บ ดึงข้อมูลฟอร์มและ URL เอกสาร
inject.js             ดักจับ API response ของหน้าเว็บ
sidepanel.html/js/css หน้าจอผลการตรวจ
lib/ocr-engine.js     OCR (Tesseract + PDF.js) และ parser เอกสารไทย
lib/rules.js          rule-based checks
lib/registry.js       ดึงทะเบียนหน่วยบริการและตรวจซ้ำ
lib/agent.js          ควบคุมลำดับการทำงานและเทียบข้อมูล
lib/ai-extract.js     โหมด Parser + AI (ส่งไฟล์ไป Gemini)
lib/tesseract/        OCR engine
lib/pdfjs/            อ่าน PDF
```

ไฟล์ `test_links.js` และ `update_css.js` เป็นไฟล์เก่าที่ไม่ได้ใช้แล้ว ลบได้
